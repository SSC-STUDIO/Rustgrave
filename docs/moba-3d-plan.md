# 3D 像素风 MOBA 模式计划（仿王者荣耀）

## 目标

把现有的「仿王者荣耀 2.5D 模式」（侧视角竞技场，运行时 `ArenaRun`，见 `docs/arena-mode.md`）
升级成真正的 3D MOBA：5v5、三条兵线、野区、河道、防御塔、水晶、兵线波次。

- 玩法：**完整照搬王者荣耀的机制**，在此基础上再加 Rustgrave 自己的改进（见 P8）。
- 画面：3D 场景，风格化渲染成**像素风**（低分辨率整数放大、色阶光照、单纹素描边）。
- 旧模式不动：新模式在 `scenes/moba/`、`scripts/moba/`、`assets/shaders/moba/` 下并行开发，
  做完再接入标题屏入口。

## IP 边界

- 只照搬**机制、规则和结构**（分路、塔的索敌规则、经济与成长曲线、装备栏位等）。
- 所有名字、英雄、美术、音效、UI 与文案都是 Rustgrave 原创内容，不使用任何王者荣耀素材。
- 阵营：

| 阵营 | 位置 | 主色 / 暗色 / 亮色 |
| --- | --- | --- |
| 蓝方「灰卫」 | 左下 | `#4f7db8` / `#2f4c7a` / `#8db6e8` |
| 红方「锈誓」 | 右上 | `#b23a2e` / `#6e1f1f` / `#e8735a` |

- 铭文替换为「锈核」（见 P4、P8）。

## 默认决策

- **角色**：程序化低多边形（方块拼装、顶点色、描边），不依赖外部模型资源。
- **并行开发**：旧竞技场代码一行不改；新模式自带运行时与记录。
- **先单机对 AI**，但模拟层从第一天起就是确定性的（lockstep-ready），以后可以做联机。
- **渲染器保持 GL Compatibility**：桌面与 Android 同一套管线。

## 架构

```
scripts/moba/sim/    确定性模拟：30 Hz 固定 tick、种子 RNG、一切操作都是命令
scripts/moba/view/   3D 表现：像素舞台、相机、色阶材质、角色、特效
scripts/moba/data/   英雄、装备、地图的数据描述
scenes/moba/         场景（P0 渲染验证、正式对局场景）
```

- **模拟层（sim）**：不依赖场景树，可无头运行（`MobaSim`）并直接写单元测试；
  玩家与 AI 的输入统一成「第 N tick、某玩家、某命令」；每 tick 计算状态哈希，用于回放校验与联机防不同步。
- **表现层（view）**：只读模拟状态，在两个 tick 之间插值；渲染细节不反过来影响玩法。
- **数据层（data）**：英雄数值、技能参数、装备、地图都写成数据，平衡调整不改代码。
- **`MobaRun` Autoload**：镜像 `ArenaRun` 的接口（开局、结算、结果信号、独立记录文件），
  标题屏与记录系统用同一种方式接入；不写战役存档。
- **寻路**：网格 A*（确定性、可测试），不用 NavigationServer。

## 渲染方案（P0 验证）

- **低分辨率舞台**：3D 画面渲染进 SubViewport（默认约 360 行纹素，可切 270 / 360 / 432），
  按整数倍、最近邻放大；默认铺满窗口（宽度随屏幕比例），也可切 16:9 加黑边。
- **相机**：正交投影，俯角 55°，不旋转。相机位置按「整纹素」吸附在相机平面上，
  剩下的亚纹素偏移改为把放大后的画面平移整数个物理像素：滚屏顺滑，静态物体不闪烁。
  四周多渲染 2 纹素余量，平移时不露边。
- **单位吸附**：单位的可视节点同样吸附到纹素网格，走动时只整格平移、不抖动。
- **色阶光照**：自定义 `light()`，三档明暗；颜色来自项目调色板的顶点色，顶点 alpha 表示自发光；
  所有刚体部件共用一个材质并合并网格，一个部件一次绘制调用。环境光在 `light()` 里随太阳一起加（原因见下）。
- **描边**：默认用「外壳」（反向外扩网格），宽度约 1 纹素，缩放或换分辨率时自动重建；
  可选屏幕空间深度描边。
- **可选后处理**：Bayer 4×4 抖动（锚定在世界纹素上，滚屏不游动）、调色板锁定
  （项目 16 色 + 22 个扩展色，含地面用的土色阶）。
- **其他**：12 帧/秒的步进动画、圆形贴地阴影 + 太阳实时阴影、程序化 32×32 灰度纹理
  （按世界坐标投影，纹素密度处处一致）、色带流动的熔岩、火盆与水晶下分档的「光池」（代替点光源）。

### Compatibility 渲染器的光照约束（P0 实测）

以下几条都在 Godot 4.7 的 Compatibility 渲染器上逐像素读回验证过，之后所有 3D 像素内容都要遵守：

| 现象 | 规则 |
| --- | --- |
| 带阴影的太阳在额外一遍里绘制，并在 sRGB 编码**之后**叠加到画面上 | Environment 的环境光关掉（`AMBIENT_SOURCE_DISABLED`），由 toon 着色器在太阳的 `light()` 里加环境光；否则开关阴影会让整个画面变亮或变暗 |
| 点光源会照亮包围盒与它相交的整个网格（超出照射范围也算），同样在 sRGB 空间叠加，容易过曝 | 不用点光源；火盆、水晶等用叠加贴地的光池（`light_pool.gdshader`） |
| 无光照（unshaded）材质的输出不做 sRGB 编码 | 光池、描边、贴地阴影写的颜色就是屏幕上的颜色 |
| 网格顶点色会被渲染器自动线性化 | 顶点色直接写调色板的 sRGB 值，不要自己转换 |
| 脚本给 `source_color` uniform 赋的 Color 会原样使用，不做线性化 | 需要线性值的参数用 `vec3` 传，在脚本里换算 |
| 阴影贴图的绘制调用不计入渲染统计；开阴影时每个受光物体还会多画一遍光照 | 叠加层只显示可见绘制；性能对比时分别测开、关阴影 |

## 阶段

### P0 渲染验证场景

- 场景：`scenes/moba/RenderSpike.tscn`，编辑器里打开后按 F6，按 H 看按键说明。
- 内容：中路切片（熔岩河 + 桥、双方防御塔与水晶、墙、草丛、岩石），可操控的余烬骑士
  （过顶挥剑），循环走线的双方小兵；每个画面选项都有按键；叠加层实时显示
  FPS、绘制调用、三角形数、内部分辨率、每纹素米数。
- 验收：
  - 开启吸附时平移镜头不闪烁、不游动；
  - 描边约 1 纹素宽，缩放后仍然如此；
  - 桌面与中端 Android 机上 FPS 与绘制调用可接受（压力测试 M 键 +40 小兵时也看一眼）；
  - 画面风格经确认后，P2/P3 的正式美术才在这套管线上铺开。

### P1 确定性模拟核心

- 固定 tick 循环、定点数学、种子 RNG、命令队列、实体存储。
- 网格 + A* 寻路；移动、普攻、死亡；兵线波次；防御塔索敌规则；水晶胜负。
- 每 tick 状态哈希；无头 `MobaSim`。
- 验收：同种子 + 同命令序列 → 每 tick 哈希完全一致；录制命令回放得到同一结局；测试全绿。

### P2 地图数据化

- 一份数据描述整张地图：三路、野区、河道、墙、草丛、塔、水晶、野怪营地、出生点。
- 同一份数据同时生成模拟网格和 3D 场景几何。
- 验收：改数据即改地图，模拟与画面始终一致。

### P3 英雄操控与战斗

- 移动、普攻、三个技能 + 大招、目标选择与施法指示。
- 首批 4 名英雄：余烬骑士、炉风先驱、绞盘守渠人、梦魇。
- 里程碑（P0–P3）：**「一条路能打」**。

### P4 成长与经济

- 等级 1–15，4 级解锁大招；金币与经验；6 格装备与商店；召唤师技能。
- 锈核替代铭文；野怪营地、增益 buff、史诗野怪。

### P5 5v5 AI

- 对线、打野、团战、目标争夺；多档难度。
- 里程碑（P4–P5）：**「完整峡谷」**。

### P6 UI 与触屏

- HUD、小地图、虚拟摇杆 + 技能键（拖拽瞄准）、商店、计分板、信号标记。

### P7 美术与音频

- 英雄扩充到 10 名；技能特效、音效、音乐。
- 里程碑（P6–P7）：**「像王者」**。

### P8 Rustgrave 改进

- **招架**：时机正确可格挡并反打。
- **锈核**：4 / 8 / 12 级各选一次。
- **热量**：额外的资源条，与技能联动。
- **地图事件**：河道熔岩潮汐、「炉火躁动」事件、昼夜（接现有 `WorldClock`）、可破坏的墙。
- **AI 响应信号**：玩家标记目标，AI 队友会跟进。
- **训练、回放、观战**：回放直接复用命令录制。
- **可读性**：技能范围、危险区域、关键状态的提示更清楚。

### P9 收尾

- 标题屏入口、独立记录、设置项、Android 性能专项。
- 玩家向说明文档 `docs/moba-mode.md`。

## P0 验证结果（云端）

在云端虚拟机上用软件 GL（Mesa llvmpipe，CPU 渲染）跑过。绝对 FPS 不代表真机，主要用于对比：

| 场景（1920×1143 窗口，内部 640×382，放大 3 倍） | FPS | 绘制调用 | 三角形 |
| --- | --- | --- | --- |
| 默认视角 | 38 | 93 | 11.9k |
| 关太阳阴影 | 48 | 62 | 11.9k |
| 压力测试（+40 小兵） | 37 | 228 | 16.3k |

- **滚屏闪烁**：录 8 秒自动平移，逐帧找最佳整像素平移后统计残差（灰度差超过 24 的像素比例）。
  吸附开：中位数 1.5%，95 分位 2.9%；吸附关：6.5% / 10.7%。吸附开时的残差只出现在走动的小兵、
  熔岩动画和叠加层文字上，静态边缘不爬行；关阴影结果相同（1.45% / 2.7%），阴影边缘也不闪。
- **亮度**：开、关太阳阴影时同一位置的像素值完全一致。
- **描边**：外壳描边约 1 纹素宽，缩放后仍然如此；深度描边在 Compatibility 上可用（`reverse_z = false`）。
- **分辨率与比例**：270 / 360 / 432 行三档、16:9 黑边、1280×1024 与 1680×720 窗口下，
  画面都是整数倍放大，叠加层贴着窗口边缘。

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| 3D 像素画面滚屏闪烁 | 相机整纹素吸附 + 亚纹素画面平移；单位同样吸附（P0 已验证） |
| Android GL Compatibility 绘制调用预算 | 部件合并、地形按材质合并、叠加层实时监控 |
| 绘制调用随单位数线性增长：每个小兵 4–10 次（部件、外壳描边、贴地阴影、开阴影时的光照遍） | 接入完整兵线（P2）前把小兵改成 MultiMesh 合批或单网格骨骼动画 |
| 太阳阴影在 Compatibility 下让受光物体多画一遍（默认视角 62 → 93 次） | 低画质档关太阳阴影，只留贴地阴影 |
| Compatibility 的多光源叠加发生在 sRGB 空间 | 遵守上面的光照约束；要加新光源先读回像素验证 |
| 深度描边依赖深度纹理，移动端驱动差异大 | 只做可选项，默认外壳描边 |
| 纹理密度与画面纹素不成整数比（砖石 16 纹素/米，画面约 28 纹素/米），砖缝宽 1–2 像素不等 | 视野高度为了公平是固定的，不靠缩放凑整；P7 正式美术时按默认视野重定纹理密度 |
| 调色板锁定按窗口像素逐个计算（每像素遍历 38 色） | 如果保留这个选项，改到内部分辨率上做 |
| 确定性被浮点破坏 | 模拟层全用定点整数，不用浮点三角函数，遍历顺序固定 |
| 范围失控 | 按里程碑验收，每个里程碑都可玩、可测 |
| IP 风险 | 只借机制，内容全部原创 |
