# Rustgrave 全面升级计划（进行中）

> 本页是唯一的分阶段清单与验收标准。数值/流程细节仍以 `docs/combat-rules.md`、
> `docs/level_authoring.md`、`docs/art-spec.md` 为准。改动必须落到玩家能看见、
> 听见、操作到的内容；不以菜单数量、数值堆叠或粒子数代替体验。

## 0. 项目现状核实（本轮基线）

- 技术栈：Godot 4.7.1 + GDScript，640×360 世界 SubViewport + 1280×720 UI 设计层。
- 十章关卡、三环境主题、双 Boss、存档、键鼠/触屏、开场分镜、章节过场均已存在；
  `scripts/combat/combat_rules.gd` 已是战斗数值与反馈的唯一来源；
  `LevelSanity` 已是几何检查；`tests/` 为零依赖测试集。
- 基线核实：`tests/run_tests.tscn` 全量 **670/670 通过、0 engine errors**；
  已完成的工作区改动作为基线提交（`chore(baseline)` 提交）。
- 结论：**不要重建系统**。本轮是"可见质量与演出"升级，不是功能补齐。

## 2. 分阶段升级清单

### 阶段一：样板体验（标题 → 开场 → 第一章 → 战斗 → Boss → 第二章）

目标：把第一章做成"可以拿去给人试玩"的样板，规范随后推广。

- **1A 场景细节与光照（P0-1、P2-1）**
  - 删除 `SceneDetails` 的 ColorRect 占位，改为 `PropCatalog` 真实贴图装饰：
    锈蚀管道（`pipe_valve`）、坏机械（`broken_machine`/`girder_*`）、断链、骨渣、
    墓碑、废弃设施、生活残留、炉火排气口，全部走 `Level01Env.plant` /
    `Level01Env.plant_texture`，写 `feet` 元数据、入 `grounded` 组。
  - 按区域手排：起点台地 / 毒坑 / 中段攀爬 / 门区 / 决斗场前 / 东翼 / 炉心。
    不遮挡台缘、敌人起手和交互物。
  - 光照锚定地标（余烬巢、毒池、门、Boss 竞技场、锻炉），不写死随机坐标。
  - 验收：`level_sanity_test` / `level01_layout_test` / `wind_sway_test` 通过；
    渲染截图无悬空方块、光池落在实体上。
- **1B 一章视觉身份（P1-2、P1-3）**
  - 天空板重着色为"锈月夜"（保留原板不动，新增 `parallax_sky_rust.png`，
    `tools/gen_theme_tiles.py` 生成，幂等、可复现、CREDITS 记录派生关系）。
  - 加入地平线暖锈雾带与月光束，压住品红、抬出锈橙；远山与近景分层继续走
    `ThemeBackdrop` 明度阶梯（sky 0.13 → far 0.18 → mid 0.4 → near 0.62）。
  - 悬空台按区段混用石板/苔板/断板，打破单一重复。
  - 验收：1920×1080 与 1280×720 截图；角色与背景至少 2 档明度差；无接缝。
- **1C 主角巨剑身份（P1-1）**
  - 新增"背扛锈蚀锯齿巨剑"表现层（程序化像素、走 `Palette` 色板），
    探索/跑/跳/冲刺时可见并随动；挥砍时让位给帧动画自带剑与 `SlashArc`。
  - 开场：第一拍能看到骑士与插在地上的巨剑，起身后剑收上背。
  - 验收：截图可见巨剑；攻击不出现"双剑";`player_feel_test` / `melee_combat_test` 通过。
- **1D Boss 演出（P1-4）**
  - 刽子手：体型/轮廓强化、竞技场火盆与侧光、进场镜头与血条时序、
    二阶段可辨识（斧上余烬 + 吼叫）、死亡演出与章节交接。
  - 验收：Boss 渲染截图可见完整剪影与前摇；`executioner_boss_test` 通过。
- **1E 演出与回归修复（P0-2、P2-2）**
  - 修正开场第一拍与交还操作；`CinematicAcceptance` 去重抓帧、门禁可靠。
  - 验收：开场 11 张连续帧 + `opening_cinematic_test` / `cutscene_safety_test` 通过。
- **1F 音频/界面补齐（P2-3 及第一章听感）**
  - 首章环境声、地面脚步差异、Boss 战段音乐/声景切换、拾取/机关提示音；
    HUD 毒素条与 Boss 血条可读性。
  - 验收：音量平衡无爆音；截图/录屏；音频键回归测试。

### 阶段二：规范推广到其余章节

- 2A 每章视觉身份与场景细节（三至十章）：主题白名单、历史细节（机械/墓/管道/炉火）、
  光源锚定、平台变化。验收：逐章渲染机位 + `level_sanity`。
- 2B 关卡节奏与支路：每章一个玩法变化、可选支路奖励、地标引导。
  验收：输入验收首章与十章基础能力路线。
- 2C 全部 Boss 与章节演出：登场、阶段、死亡、过场。
  验收：`chapter_progression_test` + Boss 渲染。

### 阶段三：系统完善与最终验收

- 3A 音频层次与 UI 统一（设置/触屏安全区/字体边界）。
- 3B 可靠性与性能：临时节点上限、信号重复连接、暂停/死亡/切场/读档恢复。
- 3C 最终验收：全量测试、真实输入路线、桌面尺寸矩阵、截图/录屏归档、
  `docs/acceptance.md` 记录。触屏/真机单独报告，不以桌面模拟冒充。

## 3. 验收总则

1. 每个改动必须有证据：测试通过 + 实际渲染/运行截图（或输入验收日志）。
2. 视觉验收用 `PeekLive` 实机渲染；演出验收用 `CinematicAcceptance`；
   通关验收用 `run_input_acceptance.ps1`。三者不可互相冒充。
3. 每完成一个完整改动即提交 Git；只暂存本轮明确涉及的文件。
4. 已知未验证项（真机触屏、实体显示器性能、人工手感）在最终报告单独列出。
