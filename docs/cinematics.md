# 开场与过场演出

开新游戏时，第一章醒来前播放三段约 13 秒的像素分镜：锈剑 / 无名者之墓 / 地下炉心。每段有独立构图、分层移动、灰烬或余烬、标题与旁白，镜头之间交叠淡变，最后回到实际关卡并接苏醒演出。沿用已有角色、墓园贴图与音效，锈剑与炉心由绘制代码生成。

按 Enter、空格或点击「跳过开场」可跳过整段序章。章节和普通剧情的「继续」逐拍推进。暂停时分镜、粒子、交叠与提示一起冻结。跳过、死亡中断、切场均清理画面和镜头托管；继续游戏及死亡读档不重复序章。

十章首次到达的标题由现有章节元数据生成，显示 2.6 秒，再接原来的剧情旁白。Boss 实际宣告登场时显示短暂名号、铁色横幅与余烬；名号自行退场，战斗控制与判定时机仍由原有战斗逻辑负责。

## 作者接口

Director 步骤 `{"kind": "tableau", "id": "relic"}` 切换分镜；`id` 可用 `relic`、`grave`、`furnace`、`world`、`chapter`、`boss`。`world` 回到游戏；`chapter` / `boss` 用 `title` / `subtitle` 传文字。带 `seconds` 时为可继续的计时拍，不带时即时切画面。`ChapterLevel.chapter_card(title)` 从「锈墓・章节 — 地名」生成章节拍。

`fx` 步骤支持 `target`（Node2D 或世界坐标），保证冲击环、残芯脉冲落在剧情对象身上。

画面使用固定 640×360 构图，在原有 UI 适配层显示。两张画布循环复用，52 个程序化微粒直接绘制，不持续创建粒子节点。标题与旁白在独立层显示。

## 复验

```powershell
./tools/run_tests.ps1 -CaseFilter cinematic
```

实际渲染截图用 Godot 打开 `scenes/tools/CinematicAcceptance.tscn`；需要 OpenGL 窗口环境。该工具使用单独的临时存档，产出至 `screenshots/acceptance/cinematics/`：三个开场镜头、恢复游戏、章节与 Boss 名号、640×360 小窗口，以及 `report.json`。这些是演出播放及视觉夹具，不能代替全流程通关或真实手机验收。原有 OpenGL 退出阶段可能报告纹理 / CanvasItem 资源清理告警；需同时查看渲染日志，不只看截图报告。

2026-10-16 当前工作区验证：397/397 回归测试通过，运行期引擎错误为 0；其中开场及演出生命周期测试 11 项。实际 OpenGL 播放产出 7 张截图，序章正常结束并标记 `opening_seen`。已人工检查按钮边界、字幕、两种窗口尺寸，以及 Boss 横幅避开角色脚下区域。退出日志仍有 CanvasItem / 纹理资源清理告警，与既有 display 验收日志同类，尚未修复。
