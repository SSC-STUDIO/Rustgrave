# 开场与过场演出

开新游戏时，黑场只走标题那一次淡入，揭开的是第一章的真实墓园，不再盖程序化幻灯片。同一条可跳过的剧本约十二秒：先停在骑士身上（「剑先锈了。里面还有人。」），镜头移到已经种在地上的坟（「你不是被选中的。刮锈的偶，自己先锈透了。」），再回到骑士，余烬巢上起一次火（「炉还在下面。你得把他们带下去。」），然后在同一条遮幅里显示「锈墓・壹 — 腐液回廊」。章节卡退去时收起遮幅、交还镜头并解锁。没有第二段醒来。

按 Enter、空格或点击「跳过开场」会跳过整段，包括章节卡。继续游戏、死亡读档、已经看过都不重播。`opening_seen` 和 `wake` 在整段正常结束或跳过时一起点上；死亡或切场中断则两点都不点，也不写结局。

十章首次到达的标题由现有章节元数据生成，显示 2.6 秒，再接原来的剧情旁白。Boss 实际宣告登场时显示短暂名号、铁色横幅与余烬；名号自行退场，战斗控制与判定时机仍由原有战斗逻辑负责。

## 作者接口

Director 步骤 `{"kind": "tableau", "id": "chapter"}` 或 `"boss"` 显示卡片；`world` 回到游戏。`chapter` / `boss` 用 `title` / `subtitle` 传文字。带 `seconds` 时为可继续的计时拍，不带时即时切画面。`ChapterLevel.chapter_card(title)` 从「锈墓・章节 — 地名」生成章节拍。开场不使用分镜 id，它只推动关卡里的 `cam_focus` 和底部字幕。

`fx` 步骤支持 `target`（Node2D 或世界坐标），保证余烬、冲击环、残芯脉冲落在剧情对象身上。

章节卡和 Boss 名号使用固定 640×360 构图，画在原有 UI 适配层上。Boss 名号上的余烬是有上限的直接绘制，不持续创建粒子节点。

## 复验

```powershell
./tools/run_tests.ps1 -CaseFilter cinematic
```

实际渲染截图用 Godot 打开 `scenes/tools/CinematicAcceptance.tscn`；需要 OpenGL 窗口环境。该工具使用单独的临时存档，把第一章载进画面壳，产出至 `screenshots/acceptance/cinematics/`：骑士、坟、余烬巢三拍、回到可操作的墓园、章节卡、Boss 名号、640×360 下的章节卡，以及 `report.json`。这些是演出播放及视觉夹具，不能代替全流程通关或真实手机验收。原有 OpenGL 退出阶段可能报告纹理 / CanvasItem 资源清理告警；需同时查看渲染日志，不只看截图报告。
